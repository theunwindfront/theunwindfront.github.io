01 · Why utility-first

Plain CSS gets messy as a project grows

style.css — after one semester project

/* style.css */ .card { padding: 24px; border-radius: 12px; } .card-title { font-size: 20px; } .card-title--big { font-size: 28px; } .btn-primary { background: #0ea5e9; } .btn-primary-new { background: #0284c7; } .btn-primary-new-2 { ... } .home .sidebar .card .title { ... } /* nobody dares delete anything */

Naming everything

Every element needs a class name before you can style it. .card-title--big? .big-card-title?

Jumping between files

HTML in one tab, CSS in another, hunting for which selector wins.

CSS that only grows

Old rules might still be used somewhere, so they stay forever.

Ask: who has had a style.css that kept growing? Who has written btn-new-2? These are the problems Tailwind is designed around.

01 · Why utility-first

Tailwind is a utility-first CSS framework

Instead of writing new CSS, you combine small ready-made classes. Each class does exactly one job.

p-4padding: 1rem;
mt-8margin-top: 2rem;
flexdisplay: flex;
text-centertext-align: center;
font-boldfont-weight: 700;
rounded-lgborder-radius: 0.5rem;

Spacing follows one scale: 1 unit = 0.25rem (4px), so p-4 = 16px and mt-8 = 32px.

Stress: Tailwind is still CSS. You need to know what padding and flex do — Tailwind just gives them short names and a consistent scale.

01 · Why utility-first

Same button, two ways

Traditional: HTML + a CSS file

<button class="btn">Enroll</button> .btn { background: #0369a1; color: white; padding: 8px 16px; border-radius: 8px; font-weight: 600; } .btn:hover { background: #075985; }

Tailwind: everything in the HTML

<button class="bg-sky-700 text-white px-4 py-2 rounded-lg font-semibold hover:bg-sky-800"> Enroll </button> /* no CSS file to write */

Same result. No class name to invent, no second file, and the styling is visible where it is used.

Point out px-4 = 16px and py-2 = 8px, matching the left side exactly. Hover over the button.

01 · Why utility-first

A short history of Tailwind

Created by Adam Wathan and team. It started as a side project and grew into one of the most widely used CSS frameworks.

2017

First release

The utility-first idea goes public.

2019

v1.0

First stable version for real projects.

2021

v3

On-demand engine: CSS is generated only for classes you use.

2025

v4 · today

Rebuilt, faster engine. Configuration moves into CSS.

Everything today is v4. Online tutorials are often v3 — mostly the same classes, but set up differently.

Keep this to one minute. The key takeaway is the version note: when students search, they should check which version a tutorial uses.

01 · Why utility-first

How Tailwind builds your CSS

STEP 1

You write classes

In HTML, JavaScript, JSX, Vue… any file in your project.

→

STEP 2

Tailwind scans

It reads your files and collects every class name it finds.

→

STEP 3

Only those ship

The final CSS has just the classes you used. Nothing unused.

⚠ The one gotcha

Tailwind reads files as plain text. It cannot run your code, so build class names in full.

won't work class="bg-${color}-500"
works const colors = { red: 'bg-red-500', blue: 'bg-blue-500' }
This is the most common beginner bug. If a class "does nothing", check whether it appears as a complete string somewhere in the source.

02 · Set up in 2 minutes

Two ways to start

A · Play CDN

for practice

One script tag. No install. Perfect for labs and trying things out.

<head> <script src="https://cdn.jsdelivr.net/npm/ @tailwindcss/browser@4"></script> </head> <body> <h1 class="text-3xl font-bold text-sky-700"> Hello, Marwadi! </h1> </body>

Write the src URL on one line — it is split here only to fit.

B · Vite project

for real apps
# 1. install npm install tailwindcss @tailwindcss/vite
// 2. vite.config.js import { defineConfig } from 'vite' import tailwindcss from '@tailwindcss/vite' export default defineConfig({ plugins: [tailwindcss()], })
/* 3. src/style.css */ @import "tailwindcss";
Use the CDN for today's exercises. Vite if you are building a JavaScript app (then npm run dev). For plain HTML projects, the CLI on the next slide is even simpler.

02 · Set up in 2 minutes

No framework? The Tailwind CLI

# 1. in an empty project folder npm install tailwindcss @tailwindcss/cli
/* 2. src/input.css */ @import "tailwindcss";
# 3. build, and rebuild on every save npx @tailwindcss/cli -i ./src/input.css -o ./src/output.css --watch
<!-- 4. src/index.html --> <link href="./output.css" rel="stylesheet">

Needs Node.js — check with node -v. Works with plain HTML, JavaScript, PHP… any files.

Two editor tools worth installing

Tailwind CSS IntelliSense

VS Code extension: autocomplete, colour previews, and hover to see the real CSS of any class.

prettier-plugin-tailwindcss

Sorts classes into a consistent order every time you save. Fewer arguments in code review.

The CLI is the simplest real setup: four steps, no framework. Keep the --watch command running while you work; it regenerates output.css whenever you save an HTML file.

04 · Responsive, states, theming

Responsive: mobile first, then add prefixes

(none)all screens
sm:≥ 640px
md:≥ 768px
lg:≥ 1024px
xl:≥ 1280px
2xl:≥ 1536px

Unprefixed classes apply everywhere. A prefix means "from this width and up".

grid-cols-1 sm:grid-cols-2 lg:grid-cols-4
375px
Drag the slider slowly from phone to laptop. Highlight that grid-cols-1 stays "on" but gets overridden by bigger prefixes. Common mistake: using sm: to mean "small screens only".

04 · Responsive, states, theming

Four responsive patterns you will use all the time

Stack on phone, side by side on laptop

class="flex flex-col md:flex-row gap-6"

Show or hide by screen size

class="hidden md:block" desktop only class="md:hidden" mobile only

Bigger text on bigger screens

class="text-2xl md:text-4xl lg:text-6xl"

Only below a size, or between two

class="max-md:px-4" < 768px class="md:max-lg:grid-cols-2" 768–1023
Design the phone layout first with no prefixes, then add md: and lg: for bigger screens. Remind them: the page needs the viewport meta tag, or phones will zoom out and ignore breakpoints.

04 · Responsive, states, theming

Container queries: respond to the box, not the screen

The same card can sit in a narrow sidebar and a wide main area. With container queries it adapts to wherever it is placed.

<div class="@container"> <div class="flex flex-col @md:flex-row gap-4"> <img class="@md:w-48" …> <p>Course details…</p> </div> </div>

@container marks the parent. @md: means "when that box is at least 28rem wide". Built into v4 — no plugin.

in a narrow sidebar

in a wide main area

This is a newer CSS feature, now in all modern browsers. Good to know — it makes components truly reusable. Do not spend more than two minutes here.

04 · Responsive, states, theming

Style a child from its parent: group & peer

hover the card → the arrow moves

<a class="group rounded-xl bg-white p-6 hover:bg-sky-50"> Register for the workshop <span class="group-hover:translate-x-2 …">→</span> </a>

bad email → the message appears

<input type="email" class="peer …"> <p class="hidden peer-invalid:block text-rose-600"> Please enter a valid email </p>

group goes on the parent. peer goes on an earlier sibling.

live · try it
Hover the card, then type "abc" in the email box — the message appears without any JavaScript. Note: peer must come BEFORE the element it affects.

04 · Responsive, states, theming

Accessible by default: four habits

sr-only

Text for screen readers only — e.g. a label for an icon-only button.

<span class="sr-only">Close menu</span>

focus-visible:

Shows a ring for keyboard users without showing it on mouse clicks.

"focus-visible:ring-4 ring-sky-300"

Contrast

Light text on light colours is hard to read. Use text-white on 700+ shades, dark text on 50–300.

Never remove outlines

If you add outline-none, always add a focus: style to replace it.

Try pressing Tab through a form with outlines removed — impossible to use. Accessibility is also a hiring signal in frontend interviews.

04 · Responsive, states, theming

Make it yours with @theme

src/style.css

@import "tailwindcss"; @theme { --color-brand: #0f766e; --font-display: "Poppins", sans-serif; --breakpoint-3xl: 1920px; }

index.html

<h1 class="font-display text-brand 3xl:text-6xl">

One variable, many classes

--color-brand creates bg-brand, text-brand, border-brand…

Config lives in CSS

Tailwind v4 needs no tailwind.config.js. Older v3 tutorials use one — that is the difference.

Students will find many v3 tutorials online. Tell them: if a tutorial edits tailwind.config.js, it is v3; in v4 the same thing goes in @theme.

05 · Real projects

Need an exact value? Use square brackets

ClassGenerates
w-[327px]width: 327px
bg-[#1da1f2]a colour that is not in the palette
grid-cols-[240px_1fr]fixed sidebar + flexible content (_ = space)
top-[calc(100%+8px)]any CSS value, even calc()

Use them sparingly

If you type the same bracket value three times, it belongs in @theme — so the whole team gets a proper class name.

Arbitrary values are the escape hatch for pixel-perfect designs from Figma. Too many of them means you are fighting the design system.

05 · Real projects

"The same 12 classes on every button?" — reuse them

first choice a component or function — JS, React, Vue…

// button.js — write the classes once const btn = 'rounded-lg bg-sky-700 px-4 py-2 font-semibold text-white hover:bg-sky-800'; function Button(label) { return `<button class="${btn}">${label}</button>`; } // use it anywhere list.innerHTML += Button('Enroll');

sometimes @apply in CSS

@layer components { .btn { @apply rounded-lg bg-sky-700 px-4 py-2 font-semibold text-white; } }

Why components first?

@apply brings back naming and a second file — the problems we started with. Use it for small things like third-party HTML you cannot edit.

Loops also remove repetition: a loop over a courses array renders the same card markup once in the source. Students using plain HTML can copy-paste for now; in projects, use components.

05 · Real projects

Plugins & component libraries

add a plugin in your CSS

@import "tailwindcss"; @plugin "@tailwindcss/typography"; @plugin "@tailwindcss/forms";
<article class="prose lg:prose-xl"> <!-- blog post from a CMS: nicely styled --> </article>

@tailwindcss/typography

One prose class styles a whole article: headings, lists, links, quotes.

@tailwindcss/forms

Sensible default styles for inputs, selects and checkboxes.

Component libraries

daisyUI, Flowbite, shadcn/ui and others give you ready-made buttons, modals and navbars built on Tailwind.

Install with npm, then add the @plugin line. Advise students to learn the plain utilities first, then use libraries to move faster.

Wrap-up

Is Tailwind right for your project?

✓ Strengths

Fast to build — no switching between files.

Consistent design — spacing and colours come from one scale.

Small CSS — only the classes you use are shipped.

Built in — responsive, hover, focus and dark mode.

− Trade-offs

Long class lists — HTML can look busy at first.

Class names to learn — the editor extension helps a lot.

You still need CSS — Tailwind is CSS with short names.

Repetition — move repeated markup into components or partials.

Be honest: Tailwind is a tool, not a replacement for learning CSS. Students who understand the box model and flexbox pick up Tailwind in a day.
